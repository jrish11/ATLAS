# Windows Python native component review — candidate only

The experimental runtime candidate is the official CPython 3.13.17 x64 embeddable ZIP whose SHA-256 matches its [official SPDX SBOM](https://www.python.org/ftp/python/3.13.17/python-3.13.17-embed-amd64.zip.spdx.json). The current successful Windows CI build did not test this runtime or the proposed Pillow 13.0.0 dependency. The candidate is not approved for release by this static review.

## Exact-source notices and provenance

All ten named native dependency source families from the CPython SBOM were downloaded for static inspection, including both mpdecimal versions where listed. Their SHA-256 values matched the SBOM. `notices/python-native-3.13.17/manifest.json` records source URLs, archive hashes, exact member paths and extracted notice hashes. It includes the available bzip2, expat, HACL*, libb2, libffi, mpdecimal, OpenSSL, xz and zlib notices. The SQLite source archive has no standalone license file; its amalgamated source contains the author's copyright disclaimer, and the included official SQLite copyright page states that deliverable SQLite code is public domain. The SBOM has multiple NOASSERTION license conclusions and is an inventory, not itself a completed license analysis. The Python archive's own LICENSE is separately extracted by `collect-python-notices.py`.

The proposed Pillow 13.0.0 cp313 Windows wheel contains eight `.pyd` binaries. Its exact wheel LICENSE is extracted into `PYTHON-PACKAGES.txt` and includes extensive third-party notices, including FreeType, HarfBuzz, libjpeg-turbo and libtiff. The source archive list and license text do not by themselves prove every statically linked library or enabled feature in each wheel binary. Compare the exact Pillow wheel's build manifest and native components before deciding the final notice bundle is complete.

The uiautomation 2.0.29 wheel contains `UIAutomationClient_VC140_X64.dll` (SHA-256 `e07344791d60d96e164fc003008c1102275face5d203cea40178ad51cbb3d4db`) and `UIAutomationClient_VC140_X86.dll` (`a07d5e2bce0da2847b254a1a258ce39fa6fb401baa7a8979757bc2897c7b30fe`). Both are byte-identical to the package author's `Python-UIAutomation-for-Windows` repository files at commit `10daaeb3361748670959fcf1d12bf5d39616c091`. The package's wheel includes Apache 2.0 text, extracted by the notice collector. The author identifies the separate `UIAutomationClient` C++ project as its DLL source. The reviewed upstream project at commit `a79dfedc3e4d46cbb63250eaefc5357bfa815109` is Apache 2.0 and includes Charlie Tangora's public-domain `gif.h`; both source notice texts are retained with hashes. A reproducible-build attestation tying that C++ commit to the wheel binaries was not found, so this establishes matching publisher-hosted binaries and source provenance, not an independently verified binary build.

## Specific remaining redistribution and verification gate

The Python embeddable ZIP includes `vcruntime140.dll` and `vcruntime140_1.dll`. Microsoft's [Visual C++ redistribution guidance](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files) states that distributing the Visual C++ Runtime package or individual binaries is limited to licensed Visual Studio users and subject to Microsoft's software license terms. Before distributing these two files, the publisher must verify its applicable Visual Studio redistribution rights, the relevant Microsoft terms and the exact runtime files, or obtain and review an alternative authorized deployment approach. Python's PSF license and the .NET Library License do not independently establish that permission. No publisher license entitlement was inspected or assumed here.

Also verify exact xz/liblzma and OpenSSL binary/source correspondence and any enabled optional components, Pillow native third-party notices, the SDK and .NET runtime redistribution terms described in `WINDOWS-CI3-DEPENDENCY-EVIDENCE.md`, and any obligations triggered by packaging. Include the extracted source notices, wheel notices, upstream Atticus MIT, Plip license, exact NuGet notices and any additional required notices in the release candidate. Current PyPI metadata has vulnerability records for the production Pillow 11.0.0; the 13.0.0 candidate must be checked again and pass Windows tests. No advisory snapshot establishes the absence of vulnerabilities.

The maintainer-supplied native sources, licenses and published wheel binaries were inspected without execution. The proposed Python runtime, the relocated package, WebView2 setup, microphone, tray, Claude account flow, approvals and cancellation still need native Windows verification. Codex tasks remain disabled.
