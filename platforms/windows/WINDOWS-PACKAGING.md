# Windows candidate packaging handoff

`package-atlas.ps1` is an untested assembly script, not an installer or a public download. It accepts four existing local paths: a successful `dotnet publish` directory, an independently prepared Windows x64 Python runtime with the exact runtime dependencies installed, a reviewed license notice directory, the separately supplied upstream `LICENSE-Plip`, and a new output directory. It copies app files and runtime together, uses app-relative `runtime\python.exe` when no development `atticus.json` is present, and runs Python import, Python self-test, and native self-test checks. The script does not download or publish anything. The output must be moved to a new path and tested on a clean Windows machine before any claim of portability.

Example after all inputs have been prepared and reviewed:

```powershell
.\package-atlas.ps1 -BuildDir C:\atlas-work\publish -RuntimeDir C:\atlas-work\runtime -NoticeDir C:\atlas-work\notices -PlipLicense C:\atlas-work\LICENSE-Plip -OutputDir C:\atlas-work\candidate
```

Before assembly:

1. Build and test the precise public repository commit on Windows. Preserve the commit ID and CI run URL. The project targets x64, .NET 10, and Windows build 19041 or later.
2. Prepare a standalone, redistributable, x64 CPython runtime from a trusted official distribution, with compatible reviewed dependencies. The original Pillow 11.0.0 pin has known advisories and is not approved for distribution. See WINDOWS-RUNTIME-CI.md for the experimental updated candidate and tests still required. The runtime must work after copying and without a system Python installation. For an embeddable Python distribution, configure its isolated `._pth` file to find the installed dependencies; do not assume a copied virtual environment is relocatable. Review pinned wheel provenance, hashes and all transitive dependencies. Verify runtime installation and paths on the target machine; this repository does not yet automate those steps.
3. Inventory every shipped component from Python distribution and wheel `dist-info` metadata, the exact NuGet assets in `project.assets.json`, and the self-contained .NET runtime. Create and review four UTF-8 notice files: `PYTHON.txt`, `PYTHON-PACKAGES.txt`, `DOTNET.txt`, and `NUGET.txt`. They must contain required license texts, copyright notices and applicable attribution for every shipped dependency and transitive dependency, not merely package names. Include source-offer or other obligations if any dependency requires them. Inspect native binaries bundled by Pillow, Whisper and other runtimes. `LICENSE-ATTICUS.txt` is copied from the MIT upstream license. The separate `LICENSE-Plip.txt` must be copied from the reviewed upstream UI license supplied to the assembler; its provenance must be verified. The filenames are required input checks, not evidence of legal completeness; the notice bundle has not yet been created or reviewed.
4. Examine all input files for private profiles, credentials, configuration, unrelated files and licenses. Filename filters are only a first check. The published package should not include the checkout, user settings, credentials, test logs or source-machine absolute paths.
5. Inspect the output and test a relocated copy on a fresh Windows x64 machine without Python or .NET SDK installed. Test onboarding and WebView2 dependency, microphone and speech model, startup, tray, safe approvals, cancel behavior, account flow, and normal application exit. Review signing, malware scan results, archive checksums, and release presentation separately. Claude and Codex tasks are disabled; this limited preview must not be advertised as an AI assistant.

Do not copy `build-atlas.ps1` output verbatim as a portable download: its `atticus.json` points at a local venv and source folder. `package-atlas.ps1` rejects that config and supplies the runtime relative to the app instead. Neither this script nor the resulting candidate has been tested on Windows yet.
