# ATLAS Windows CI handoff

Copy the reviewed, sanitized source from this checkout to `platforms/windows/` in the public ATLAS repository, including the MIT `LICENSE` and all source/test files needed by the job. Do not copy this checkout's `.git`, local state, `.venv-atlas`, `dist`, or the upstream `.github/workflows/checks.yml` (it runs automatically and is not SHA-pinned). Copy `.github/workflows/atlas-windows-validation.yml` to that same path at the repository root. The workflow is manual (`workflow_dispatch`) and must be present on the default branch before dispatch. Dispatch one run explicitly after review and confirmation that GitHub-hosted standard runners are enabled and the repository remains public. It has a 20-minute job timeout and retains only successful compiled build output for one day for inspection; it does not create a release.

The job uses three official Actions pinned to their full release commit IDs, sets read-only repository permission, and does not persist the checkout token. It installs the pinned Python requirements, runs the Windows-oriented upstream regression and self-tests plus fake Codex task/account tests, publishes a self-contained x64 .NET development build into the runner's temporary folder, and runs its native `--selftest`. It also parses `build-atlas.ps1`. It does not call an AI model, sign in to accounts, or verify the interactive UI. It does not execute the installer, produce a distributable package, or enable Codex tasks. `test_atlas_codex_provider.py` is a macOS-derived fixture suite and is not included as a whole here; the Windows-profile tests in `test_atlas_codex_task.py` use its fake transport.

The workflow and build have not yet run on Windows. A green result would establish only the listed automated checks, not a tested installer or interactive app. Windows sandbox, microphone, tray, onboarding, cancellation, and account behavior still need native interactive verification before release.
